# 系统开发工具基础 · 实验报告要求备忘

> 用途：后续几周撰写 LaTeX 实验报告时的参考依据
> 更新日期：2026-08-24




---

## 1. 实验报告内容要求

实验报告需包含以下三部分：

- **课上内容与结果**：每节课课上给助教检查的 4 个主题题目的内容及运行结果。
- **课后练习内容与结果**：每次课完成 >10 个实例的练习内容与运行结果。
- **解题感悟**：做题过程中的思考、遇到的问题、解决方式与收获。

---

## 2. 代码与练习提交规范

- 每次课程的报告、练习、代码需上传到个人 **GitHub** 或 **Gitee** 账号。
- 必须有 **commit 记录**，**禁止单次全量提交**（应分多次、按阶段增量提交，保留完整的 git 历史）。
- 将 **仓库链接** 和 **commit 记录截图** 写入实验报告。

**commit 分阶段策略（课上 / 课后两个阶段）**：

- 按「课上」「课后」两大阶段分次提交，禁止一次性全量提交。
  - **课上阶段**：课上 4 个主题题目，可每题一次 commit（或按题目分组提交）。
  - **课后阶段**：课后 >10 个实例练习，可几个实例一次 commit，分多次完成。
- 报告中对应位置放 commit 记录截图：
  - **课上内容与结果** 小节末尾 → 贴「课上阶段」的 commit 记录截图。
  - **课后练习与结果** 小节末尾 → 贴「课后阶段」的 commit 记录截图。
  - 附录 → 仓库链接 + 本周完整 commit 记录截图（可选，用于整体展示）。

> 这样既满足了"禁止单次全量提交"的要求，又能让截图与报告内容一一对应，不会重复。

---

## 3. LaTeX 模板要求

- 必须使用 **LaTeX**，并且 **自己设计自己的模板**（不直接套用现成模板）。
- **每周提交一份独立的实验报告 PDF**（Week 1、Week 2 …），模板是「单周报告」的可复用骨架，每周围绕同一份模板生成新报告。
- 模板需覆盖实验报告的完整结构，建议包含以下元素：

**（1）页眉 / 封面**
- 页眉：姓名（曾奕豪）、课程名称（系统开发工具基础）、当前周次
- 封面或标题区：课程名、题目（如「实验报告 — 第 N 周」）、姓名、日期

**（2）章节结构（按实验内容要求）**
- 按课上 / 课后 / 感悟三大块组织，建议结构：
  - 课上内容与结果 —— 开头先简述本周实验的主题、目标与涉及的工具；再列 4 个不同主题题目：题目要求 → 代码 → 运行结果截图；小节末尾附**课上阶段 commit 记录截图**
  - 课后练习与结果 —— >10 个实例：题目 → 代码 → 运行结果；小节末尾附**课后阶段 commit 记录截图**
  - 解题感悟 —— 思考、遇到的问题与解决、收获
  - 附录：GitHub/Gitee 仓库链接 + 本周完整 commit 记录截图

**（3）排版要素**
- 代码插入环境（`listings` / `minted`），带语言高亮
- 结果截图排版：统一宽度、带题注（`\caption`）、引用编号
- 页码
- 标题层级（`\section` / `\subsection`）

## 4. 逐周检查清单

每节课结束后对照检查（每周都要走一遍）：

- [ ] 完成课上 4 个主题题目，找助教检查并讲解；分多次 commit 推送到 GitHub/Gitee
- [ ] 完成课后 >10 个实例练习；分多次 commit 推送到 GitHub/Gitee
- [ ] 截图保存：课上阶段 commit 记录 + 课后阶段 commit 记录 + 仓库链接
- [ ] 按模板撰写本周实验报告（课上内容 + 课后练习 + 解题感悟 + 两阶段 commit 截图）
- [ ] 编译生成本周实验报告 PDF，提交/上传

---



## 5. 单周报告模板结构（推荐）

每份报告围绕下面这个骨架生成，周次、日期、题目内容随周更新：

```
系统开发工具基础 · 实验报告
第 N 周 —— <本周主题>

1. 课上内容与结果（开头简述本周主题/目标/工具，再列 4 个不同主题题目）
    题目一：<题目要求> → 代码 → 运行结果截图
    题目二：…
    题目三：…
    题目四：…
   （小节末尾：课上阶段 commit 记录截图）
2. 课后练习与结果（>10 个实例）
    实例 1：<题目> → 代码 → 运行结果
   …
   （小节末尾：课后阶段 commit 记录截图）
3. 解题感悟
```

**设计提示**：
- 用一个主 `.tex` 文件作为模板，每周复制为新文件（如 `week2.tex`、`week3.tex`），只改周次、日期、内容。
- 课上 4 个主题题与课后练习可定义统一的 `题目` 环境 / 宏，保证排版一致。
- 截图统一命名（如 `weekN_check1.png`、`weekN_commit_kecheng.png`、`weekN_commit_kehou.png`），便于批量引用。
- commit 按「课上」「课后」两个阶段分次提交，报告里对应小节末尾各放一张该阶段的 commit 记录截图。
